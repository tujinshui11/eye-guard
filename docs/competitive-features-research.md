## 一、参数调节的理论支撑（核查结论：**主体已建立，两个小缺口**）

### 1.1 既有依据链（`docs/eye-parameters-research.md`，2026-10-01）【已核实】

| 参数 | 取值 | 依据 |
|---|---|---|
| 色温档位 | 6500（原色）/ 5500（办公）/ 4500（傍晚）/ 3400（夜晚）/ 2700（深夜） | f.lux 实践值（6500/3400/1900 三档 + 白天不干预的刻意设计）；办公照明 CCT 建议 4000–5500K；CircadianShield 日落后 2700–3000K |
| 深夜档的科学解释 | 2700K + 低亮度 | **CIE S 026:2018 / melanopic EDI**：白天 ≥250 lux、晚间 ≤10、深夜 ≤1——压低色温与亮度是**控制视网膜 melanopic 剂量以保护褪黑素**，不只是"舒适" |
| 20-20-20 | 20 分 / 20 秒 | AAO + AOA 官方第一推荐；**文档已如实标注证据争议**（对照实验未证明精确时刻表优于宽松休息）→ 定位为默认建议、可自定义 |
| 亮度 | 手动 50–100% | 亮度匹配原则（显示白 ≈ 旁置白纸；办公室 ≈120 nits、暗室 40–60）；ISO 9241-303 工效学 |
| 低蓝光代价 | 软件路径必引入暖色偏 | TÜV Rheinland × Eyesafe 2.0（BLTF ≤ 0.085，硬件认证）；软件方案（色温偏移）的代价已如实告知用户 |

### 1.2 算法出处【已核实】

`src-tauri/src/temperature.rs:1`——色温 → RGB 使用 **Tanner Helland 黑体辐射近似**（业界通用近似，6500K 归一、只衰减不增亮）。与文档中的色温档位逻辑自洽。

### 1.3 代码与文档一致性【已核实】

`modes.rs` 七档与文档修订方案逐项一致（5500/4500/3400/2700 均按修订落地）。夜档硬件钳制（本机 gamma ramp 规则下 2700K 实际约 3300K）有如实提示。

### 1.4 两个待补的小缺口（建议）

1. **「冷白提神」8000K 档**（`modes.rs` focus 档）：调研文档未覆盖该档的依据。照明研究支持**白天高 CCT 提神**（与"白天不干预节律信号"方向一致），建议补一句来源或说明，消除"拍脑袋"嫌疑。
2. **亮度滑块下限 10%**：文档结论是"无环境光传感器时保持手动 50–100%"；滑块允许到 10%——低亮度+软件遮罩下对比度损失显著，建议 UI 侧对 <50% 给一句说明（"过低亮度可能损失对比度"）。

## 二、同类项目可借鉴清单

### 2.1 三家对照（f.lux / Iris / 系统夜灯）

| 维度 | f.lux【已核实】 | Iris【已核实】 | Windows 夜灯【常识】 | 艾斯现状 |
|---|---|---|---|---|
| 核心机制 | **地理位置 + 日出日落** → 每日定制光照曲线（含四季变化） | 环境光匹配 + 昼夜蓝光调节 | 色温滑块 + 计划（日落→日出） | 手动档位 + 时间调度（简单版） |
| 色温范围 | 默认夜间 3400K；可解锁 2700K 及更低（1200K presets） | 3×9 预设矩阵 | 单滑块（约 2000–6500K） | 2000–10000K 滑块 + 7 档 |
| 场景档位 | Bedtime / Movie / Color filters | **9 类**：Health/Sleep/Reading/Programming/Biohacker/Sunglasses/Dark/Movie/Overlay | — | 7 档（原色/提神/办公/阅读/傍晚/夜晚/深夜） |
| 应用联动 | **色彩关键应用自动暂停**；全屏影视/游戏自动暂停 | 预设自动切换 | — | **色彩敏感应用白名单**（同思路 ✓） |
| 快捷键 | **Alt+End 暂停 1 小时**；Alt+Shift+PgUp/PgDn 微调 | — | — | 托盘/热键调色温（**无一键暂停滤镜**） |
| 节律教育 | v4「Circadian response」：改设置时显示对昼夜节律的影响 | 营销页强调褪黑素 | — | 仅"实际生效 ≈ X K"硬件钳制提示 |
| 行为助推 | Backwards alarm（"离起床还有 X 小时"） | — | — | 无 |
| 硬件联动 | **笔记本背光变暗时自动加暖**；Philips Hue 联动（LAN API） | **无 PWM 调光**（说法谨慎，见下） | — | 背光（WMI）+黑纱双通道（**调光能力反而更底层**） |
| 适应引导 | 建议从 fluorescent→halogen 渐进（几天适应） | — | — | 无 |

### 2.2 借鉴建议（按性价比排序）

| 优先级 | 借鉴点 | 说明 | 成本 |
|---|---|---|---|
| **P1** | **一键暂停滤镜**（N 分钟 / 到日出） | f.lux 的 Alt+End 是最常用的"让路"功能：对色、开会、观影时快速切回原色。与现有托盘/热键/白名单体系天然契合 | 低（复用 restore/reenable 链路 + 计时器） |
| **P1** | **日落跟随（地理位置）** | f.lux 的核心机制、也是调研文档已列的"后续迭代"。定位→日出日落时刻→自动曲线，避免用户手动切换 | 中（定位 + 天文算法或现成 API） |
| **P2** | **全屏/影视自动挂起** | f.lux 的全屏检测：看电影/打游戏时自动回正色彩（我们的白名单只覆盖应用维度） | 中（前台窗口全屏检测——appwatch 已有前台监控基础） |
| **P2** | **节律影响可视化** | 把"当前设置"翻译成"对褪黑素/节律的影响程度"（低/中/高）——f.lux v4 的教育式交互，强化产品专业感 | 低（基于现有色温档位做映射文案） |
| **P3** | **背光-色温联动** | f.lux：笔记本背光调暗时自动加暖。我们亮度控制更底层（WMI 背光），联动逻辑可加：亮度 ↓ → 色温微暖 | 低 |
| **P3** | **场景档位扩展**（Movie / Sunglasses 式） | 借 Iris 的 `Movie`（色温回正 + 亮度稍降）与 `Sunglasses`（强遮罩）思路 | 低（加档位数据即可） |
| **P3** | **适应引导文案** | 首次切到深夜档提示"需要几天适应，可先试试傍晚档"（f.lux 的渐进引导） | 极低（一句提示） |

### 2.3 明确**不建议**跟进

- **Iris 的「无 PWM 调光」卖点**：PWM 是屏幕硬件的背光调光方式，软件层（gamma/遮罩）无法真正改变它；Iris 的表述有明显营销成分。艾斯的背光通道（WMI）反而能真实触及硬件亮度——保持现状即可，不做类似宣称。
- **无限下探色温（1200K 级）**：软件方案在极低色温下对比度损失显著，且本机驱动有钳制——不做虚假承诺（与既有文档"明确不采用"一致）。
